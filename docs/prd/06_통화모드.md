# 06. 통화 모드

## 1. 확정 사항
- **링크 통화 = 주력**, **스피커폰 방식 = 보조**.
- 청인은 **설치·가입 없이** 링크(또는 QR)만 누른다.
- 양방향: 농인 글 → 청인에게 음성, 청인 말 → 농인에게 자막.
- 일반 전화망(010 번호로 직접 걸기)은 출시판 과제 (통신 연동 계약 필요).

## 2. 링크 통화 — 구조
행사판에서는 영상·음성 통화 기술(WebRTC)을 쓰지 않고, **실시간 메시지 연결(WebSocket)로 "글·음성·자막"만 주고받는** 단순 구조를 쓴다. 농인은 말을 하지 않으므로 실시간 음성 회선이 필요 없고, 방화벽·연결 문제도 훨씬 적다.

```
농인 폰 (S7)                    API 서버 (api.itda.gyeot.ai.kr)              청인 폰 (S8, 브라우저)
  글 + 감정  ──WS──▶  ① 메시지 받음 → TTS 요청 → 음성 URL  ──WS──▶  ② 음성 재생 + 자막 표시
              ◀──WS──  ③ "상대 폰에서 재생 중" + 소리 크기     ◀──WS──  재생 진행 상황 전송
  자막 표시   ◀──WS──  ⑤ 자막 전달                         ◀──WS──  ④ 청인 말 → 글자 (폰에서 인식)
```

### 핵심 기능: "상대 폰에서 들리는 중" 확인
- 청인 폰이 음성을 재생하면서 **재생 시작 / 소리 크기(0.1초 간격) / 재생 완료** 를 서버로 보낸다 → 농인 화면의 "말하는 중" 막대와 진동/테두리 빛이 **상대 폰의 실제 재생**에 맞춰 움직인다.
- 즉, 농인은 "내 말이 지금 상대에게 들리고 있다"를 직접 확인할 수 있다.
- 청인 폰에서 5초 안에 재생 시작 신호가 없으면 농인에게 "상대 폰에서 소리가 나지 않았어요" 경고 + [다시 보내기].

### 통화 방 (call room)
- `POST /calls` → `callId`(추측 불가능한 무작위 값), 참여 링크 `https://itda.gyeot.ai.kr/c/{callId}`, QR 이미지.
- 방 유효시간: 생성 후 30분 안에 청인이 들어오지 않으면 만료. 통화 중 무활동 15분이면 종료.
- 한 방에는 농인 1 + 청인 1만 (세 번째 접속은 "이미 통화 중" 안내).
- 서버는 방 상태(연결 여부, 시간)만 메모리에 두고 **대화 내용은 저장하지 않는다.** 음성 파일은 캐시 정책(07)에 따라 짧게만 보관.

### WebSocket 메시지 형식
```jsonc
// 농인 → 서버
{ "type": "say", "msgId": "m_17", "text": "안녕하세요ㅎㅎ", "emotion": {"emotion":"joy","intensity":2,"tremor":0,"source":"auto"} }
// 서버 → 청인
{ "type": "audio", "msgId": "m_17", "text": "안녕하세요ㅎㅎ", "displayText": "안녕하세요ㅎㅎ", "emotion": {...}, "url": "https://tts.../a/abc.mp3", "fallback": false }
// 청인 → 서버 → 농인 (재생 진행)
{ "type": "playback", "msgId": "m_17", "state": "start|level|end|error", "level": 0.62 }
// 청인 → 서버 → 농인 (자막)
{ "type": "caption", "text": "네 반갑습니다", "final": true }
// 양쪽 상태
{ "type": "presence", "role": "hearing", "online": true }
{ "type": "speaking", "role": "hearing", "level": 0.4 }   // 청인이 말하는 중 표시용
```
- 연결이 끊기면 자동 재연결(1초, 2초, 4초… 최대 15초 간격). 재연결 동안 보낸 메시지는 폰에 쌓아 두었다가 재전송.
- `fallback: true` 이면 서버 음성이 실패한 것 → 청인 폰이 **자기 폰 기본 음성**으로 `text` 를 읽는다.

### 청인 말 → 자막
- 1순위: 청인 폰 브라우저의 음성 인식(Web Speech API, `ko-KR`) — 안드로이드 크롬에서 안정적.
- 2순위(인식 기능이 없거나 오류 시): [누르고 말하기] 녹음 → `POST /stt` (서버 음성 인식, 07 참조). 행사판에서는 **선택 기능**(T18에서 시간이 되면).
- 3순위: 청인이 글로 답하기 입력칸.
- 농인이 보낸 음성이 청인 폰에서 재생되는 동안은 청인 폰의 음성 인식을 잠시 멈춘다 (자기 소리가 자막으로 잡히는 것 방지).

## 3. 스피커폰 방식 (보조)
- 농인이 일반 전화를 걸고 스피커폰을 켠 상태에서, ITDA 대화 화면에 글을 치면 폰 스피커로 음성이 나와 통화 마이크를 통해 상대에게 전달된다.
- **주의(검증 필요, T19):** 일반 전화 통화 중에는 폰 기종·운영체제에 따라
  - 브라우저 소리가 작아지거나 수화부로만 나오거나 아예 멈출 수 있고,
  - 브라우저 마이크(자막)를 쓸 수 없을 수 있다.
- 그래서 행사판에서는 **"글 → 음성"만 보장**하고 자막은 제공하지 않는다. 화면에 "이 방식은 상대 말 자막이 나오지 않아요. 자막이 필요하면 링크 방식을 쓰세요" 안내.
- T19 결과 특정 기종에서 소리가 안 나오면: 안내 문구로 **"다른 폰/태블릿에서 ITDA를 켜고 통화 중인 폰 옆에 두세요"** 방법 제시 (2대 방식).

## 4. 행사장 체험 시나리오
1. 참가자 A(농인 역할)와 B(청인 역할)가 짝을 짓는다. 서로 떨어진 자리, 또는 등을 돌리고 앉는다.
2. A: ITDA 홈 → [전화로 대화] → [링크로 전화 걸기] → QR 표시.
3. B: 자기 폰 카메라로 QR 촬영 → [대화 시작].
4. A가 글을 보내면 B 폰에서 감정 음성이 나오고, B가 말하면 A 화면에 자막.
5. 스태프 안내 카드: "농인 역할은 소리를 듣지 말고 화면과 진동만으로 확인해 보세요."
