# 08. 행사 운영 · 부스 체험 부하 대응 · 비용

## 1. 부하 추정 (가정 — 리허설 측정으로 갱신)
- 행사 형태 (2026-10-21 변경): 행사 방문 약 1,000명 중 **상담 부스 방문 100~500명**. 500명이 동시에 접속하지 않는다. 부스에서 **1:1 또는 2:2로 안내**하며, 부스 안에서 같은 시간에 쓰는 사람은 **최대 5:5 (기기 약 10대)**. 참가자는 **본인 폰**으로 QR 접속한다.
- 부스 시간: 하루 8시간 × 동시 5자리 기준, 500명이면 **1인당 체험 약 5분** → 가입은 60초 안에 끝나야 하고, 스태프 안내가 중요하다.
- 본인 폰이라 부스를 떠난 뒤에도 행사장에서 계속 쓸 수 있다 → **준비 기준은 동시 사용자 50명** (부스 10명의 5배 여유).
- 50명이 평균 20초에 한 문장 → 초당 약 **2.5건** (최고치). 즐겨찾기 문구·같은 문장 반복은 캐시에서 즉시 처리된다.
- GPU 1대가 초당 처리할 수 있는 문장 수는 **T03에서 실측**한다. 초당 3건 이상이면 **GPU 1대로 충분**, 부족하면 예비 1대를 함께 켠다.
- 행사 당일 GPU: **1대 + (선택) 예비 1대**. 예비가 없어도 GPU가 멈추면 폰 기본 음성으로 넘어가므로 무음은 없다.
- 이름 정보가 최대 500명분 서버에 남으므로, 보관 기간(10 문서 Q2)을 반드시 정한다.

> 이 숫자는 가정입니다. 부하 테스트(T22)와 리허설 결과로 확정합니다.

## 2. 부하를 줄이는 장치 (모두 행사판 필수)
1. **즐겨찾기 미리 생성** (03 문서 8절) — 체험 첫 문장의 상당수가 "안녕하세요".
2. **같은 문장 캐시** — 사람마다 비슷한 문장을 친다.
3. **글자 수 100자 제한** — 화면에서 안내.
4. **대기열 + 비상 전환** — 2.5초 안에 GPU 차례가 오지 않거나 총 4초가 넘으면 폰 기본 음성으로 즉시. **무음은 절대 없다.**
5. **부스 안내 인원 조절** — 동시에 5:5를 넘지 않게 스태프가 안내 (부스 형태라 별도 입장 분산은 필요 없음).
6. **GPU 미리 깨우기** — 행사 당일은 GPU를 행사 1시간 전부터 켜 두고 `warmup` 확인.

## 3. 비용 (대략, 실제 견적은 T21에서)
| 항목 | 평소 (월) | 행사 당일 |
|---|---|---|
| 웹앱 정적 호스팅 | 무료 플랜 | 무료 플랜 (트래픽 충분) |
| API 서버 (소형 VPS) | 약 1만원 안팎 | 하루만 사양 올리기 가능 |
| GPU | 개발·시연 때만 켜기 → 약 3~4만원 한도 안에서 사용 | 24GB급 GPU 1대 (+예비 1대 선택) × 약 8시간 (시간 단위 과금) |
| 감정 AI (선택) | 사용 시 소액 | 사용 시 소액 |
| **합계** | **5만원 이하 목표** | **별도 견적 (GPU 1~2대 기준, T21에서 확정)** |

- GPU는 **반드시 사용 후 끈다.** 켜 두면 예산이 바로 넘는다. → T21에서 "켜기/끄기 스크립트"와 "잊지 않게 알림" 마련.
- 업체·요금은 자주 바뀌므로 행사 1주 전(11/5) 기준 견적을 다시 확인.

## 4. 리허설 (11/10) 체크리스트
- [ ] 실제 폰 20대 이상 (안드로이드 10대·아이폰 10대, 오래된 기종 포함)
- [ ] 행사장 와이파이 + 휴대폰 데이터 양쪽에서 접속
- [ ] QR 접속 → 가입 → 첫 음성 60초 이내
- [ ] 대면 모드: 상하 분할, 자막, 감정 칩, 단어 하이라이트, 진동/테두리 빛
- [ ] 링크 통화: 짝 5쌍 동시 (부스 최대 인원), 재생 확인 신호, 끊김 후 재연결
- [ ] 스피커폰 방식: 안드로이드·아이폰 각 2대 (통신사 다르게)
- [ ] GPU를 일부러 끄기 → (예비가 있으면) 다른 GPU로 넘어가는지 / 모두 끄기 → 기본 음성으로 넘어가는지
- [ ] 부하 도구로 동시 50명(초당 약 2.5건) 10분 유지 → 응답 시간 기록
- [ ] 농인 당사자 테스터의 의견 (가능하면 2명 이상)
- [ ] 무음 모드 폰에서 "폰 소리를 켜 주세요" 경고가 뜨는지
