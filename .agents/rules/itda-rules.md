# ITDA 프로젝트 규칙 (모든 작업에 항상 적용)

## 프로젝트
- ITDA(잇다): 농인이 글을 치면 선택한 목소리와 감정으로 말해 주고, 청인의 말은 자막으로 돌려주는 웹앱(PWA).
- 요구사항 원본은 `docs/prd/` 문서다. 문서와 다르게 만들어야 할 이유가 생기면 **먼저 묻고**, 임의로 바꾸지 않는다.
- 첫 마감은 2026-11-13 행사(참가자 약 500명). 최우선 가치는 **"복잡한 것보다 잘 돌아가는 것"**.

## 작업 방식
- 한 번에 지시받은 작업(T번호) 하나만 한다. 지시에 없는 기능·라이브러리·화면을 추가하지 않는다.
- 시작 전에 짧은 계획을 보여주고, 끝나면 ① 바뀐 파일 목록 ② 실행·확인 방법 ③ 남은 문제를 한국어로 정리한다.
- 사용자는 개발자가 아니다. 설명은 쉬운 한국어로, 명령어는 그대로 복사해 쓸 수 있게 코드 블록으로 준다.
- 테스트를 만들 수 있으면 만들고 실행 결과를 보여준다. 실패한 채로 "완료"라고 하지 않는다.
- 모르는 외부 API·라이브러리 사용법은 추측하지 말고 공식 문서를 확인한다.

## 절대 규칙
1. **무음 금지:** 어떤 오류에서도 농인이 보낸 글은 소리로 나가야 한다. 서버 음성이 실패하면 폰 기본 음성(speechSynthesis)으로 읽는다.
2. **소리에만 의존하는 안내 금지:** 모든 상태는 글자 + 색 + 아이콘(+ 가능하면 진동/테두리 빛)으로 보여준다.
3. **가짜 표시 금지:** "말하는 중" 막대·하이라이트·진동은 실제 재생 신호에 맞춰 움직인다.
4. **대화 내용은 서버에 저장하지 않는다.** DB·로그·오류 보고에 사용자가 입력한 글과 자막을 남기지 않는다. 대화 기록은 폰(IndexedDB)에만.
5. 비밀값(키·비밀번호)은 `.env` 로만. 코드와 Git에 넣지 않는다.
6. 청인용 화면(S8)은 가입·설치 없이 동작해야 한다.

## 화면(apps/web)
- React + TypeScript + Vite + Tailwind. 상태 관리는 React 기본 기능으로 충분하면 추가 라이브러리 금지.
- 모바일 우선. 폭 360px에서 가로 스크롤 없음. 기본 글자 18px 이상, 터치 영역 56px 이상, 대비 4.5:1 이상.
- 모든 문구는 한국어, 짧고 쉬운 말. 존댓말("~해요").
- localStorage·IndexedDB 접근은 항상 try/catch (사생활 보호 모드 대비).
- 오디오는 `src/audio/player.ts` 하나로만 재생한다. 아이폰 대비 첫 터치에서 AudioContext를 연다.
- 깜박임은 초당 3회 이하.
- 안드로이드 크롬과 아이폰 사파리 양쪽에서 확인해야 하는 부분은 완료 보고에 명시한다.

## 서버(services/api, services/tts)
- Python 3.12, FastAPI, 비동기 우선. API는 단일 프로세스 + SQLite로 단순하게.
- 모든 외부 호출(TTS 서버, LLM)은 제한 시간을 둔다. 기준: TTS GPU 차례 대기 2.5초 / 총 4초, 감정 AI 1.5초 (입력 중 미리 분석, 보내기는 AI를 기다리지 않음).
- 응답 형식과 경로는 `docs/prd/07_기술구조_API.md` 를 따른다. 바꿔야 하면 문서도 함께 고친다.
- TTS 서버는 외부에 직접 노출하지 않고 `X-Key` 로 보호한다.
- 로그에는 처리 시간, 상태 코드, fallback 여부만.

## 코드 스타일
- 파일·함수 이름은 영어, 주석과 사용자 문구는 한국어.
- 작은 함수, 분명한 이름. 한 파일이 400줄을 넘으면 나눈다.
- 새 패키지를 추가하면 이유를 한 줄로 보고한다.
